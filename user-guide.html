คู่มือการใช้งาน KSAP

ระบบ Accounts Payable สำหรับพนักงานบัญชี ผู้อนุมัติ และผู้ดูแลระบบ

สารบัญ ภาพรวม เข้าสู่ระบบ สิทธิ์ผู้ใช้ ตั้งค่าระบบ ผู้ขาย AP Voucher อนุมัติ จ่ายเงิน เงินมัดจำ Debit Note / Transfer กระทบยอดและตรวจสอบ รายงาน ปิดงวด แก้ปัญหา สำหรับ Developer

1. ภาพรวมระบบ

ลำดับงานหลัก: ตั้งค่าข้อมูลหลัก → เพิ่มผู้ขาย → บันทึก AP Voucher → อนุมัติ → จ่ายเงิน → กระทบยอด → ตรวจสอบรายงาน → ปิดงวด

ระบบใช้ THB เป็นค่าเริ่มต้น และคำนวณ VAT/WHT ตามข้อมูลผู้ขายหรือรหัสภาษี

2. การเข้าสู่ระบบ

  1. เปิด URL ของระบบ
  2. กรอก Email และ Password
  3. กด Sign in
  4. ระบบพาไป Dashboard เมื่อบัญชี Active และมีสิทธิ์
เข้าไม่ได้: ตรวจสอบบัญชี Supabase Auth, สถานะ Active และ Role

3. สิทธิ์ผู้ใช้งาน

Roleการใช้งานหลัก
SUPERADMIN / ADMINใช้งานทุกเมนู รวม Settings, Users และปิดงวด
AP_MANAGER / APPROVERตรวจสอบ อนุมัติ หรือปฏิเสธเอกสาร
AP_USERสร้างและแก้ไขเอกสาร AP ตามสิทธิ์
VIEWERดูข้อมูลและรายงานแบบอ่านอย่างเดียว

4. ตั้งค่าก่อนเริ่มใช้งาน

  1. Settings > Company: ข้อมูลบริษัท VAT/WHT และบัญชี GL
  2. Settings > Period: สร้างหรือเปิดรอบบัญชี
  3. Chart of Accounts: ตรวจสอบ GL
  4. AP Types: ตั้งประเภทเอกสาร
  5. VAT Rates / WHT Rates: ตั้งรหัสภาษี
  6. Payment Codes: ตั้งวิธีจ่าย
  7. Document Number: ตั้ง Prefix และเลขลำดับ
  8. Users: สร้างผู้ใช้และกำหนด Role
ตรวจสอบว่ารอบบัญชีเปิดอยู่ก่อนบันทึกธุรกรรม

5. จัดการผู้ขาย

  1. ไปที่ Vendors > New Vendor
  2. กรอก Vendor Code และ Name (English)
  3. กรอกชื่อไทย เลขผู้เสียภาษี ที่อยู่ และข้อมูลติดต่อ
  4. ตั้ง VAT Rate, WHT Rate, Credit Term และ WHT Card Type
  5. ตรวจสอบ Review & Confirm แล้วกด Save

ค้นหาด้วยรหัสหรือชื่อผู้ขาย กดชื่อเพื่อดูยอดเอกสาร ยอดจ่าย และยอดคงเหลือ กด Edit เพื่อแก้ไข

6. บันทึก AP Voucher

  1. ไปที่ AP Vouchers > New AP Voucher
  2. เลือก Document Date และ Vendor
  3. กรอก Invoice Number, Invoice Date และ Due Date
  4. เลือก VAT Type, AP Type และ WHT Code
  5. เพิ่ม Detail Lines: GL Account, Description, Debit และ Credit
  6. ตรวจสอบ Debit/Credit ให้สมดุล
  7. ตรวจสอบ Review & Confirm แล้วกด Save

เอกสารใหม่เริ่มเป็น draft จากนั้นกด Submit for Approval

สถานะ: draft, pending_approval, approved, rejected, posted, cancelled, voided

7. อนุมัติเอกสาร

  1. ผู้อนุมัติไปที่ Approvals
  2. เปิดเลขที่เอกสารเพื่อตรวจสอบ
  3. กด Approve หรือ Reject
  4. ระบุเหตุผลเมื่อระบบร้องขอ แล้วกดยืนยัน

8. สร้างรายการจ่ายเงิน

เปิด AP Voucher ที่มีสถานะ approved แล้วกด Create Payment

  1. เลือกวิธีจ่าย: Cash, Cheque, Bank Transfer, Credit Card, Offset หรือ Deposit
  2. กรอกเลขที่เช็คหรือข้อมูลธนาคารเมื่อเกี่ยวข้อง
  3. เลือกใบสำคัญใน Outstanding Invoices
  4. ระบุจำนวนเงิน ตรวจสอบ WHT และยอดสุทธิ
  5. ตรวจสอบ Payment Items และ Applied Invoices
  6. กด Save

ระบบไม่ให้จับคู่เกินยอดคงค้างของใบสำคัญ และคำนวณยอดสุทธิตาม WHT

9. เงินมัดจำและการนำไปหัก

บันทึกเงินมัดจำ

ไปที่ Deposits > New Deposit เลือกผู้ขาย กรอกวันที่ จำนวนเงิน ข้อมูลเช็คหรือหมายเหตุ แล้วกด Save

นำเงินมัดจำไปหัก

  1. ไปที่ Deposit Apply > Apply Deposit
  2. เลือกเงินมัดจำที่มียอดเหลือ
  3. เลือกใบสำคัญของผู้ขายเดียวกัน
  4. กรอกจำนวนเงิน ตรวจสอบ VAT และยอดคงเหลือ
  5. ยืนยันรายการ

10. Debit Note และ Transfer

Debit Note

ไปที่ Debit Notes > New Debit Note กรอกผู้ขาย วันที่ เลขอ้างอิง และ Detail Lines พร้อม GL Account, Debit, Credit จากนั้นตรวจสอบยอดรวมและบันทึก

Vendor Transfer

ไปที่ Transfers เลือกผู้ขายต้นทาง ผู้ขายปลายทาง จำนวนเงิน วันที่ และ Remark แล้วบันทึก ตรวจสอบข้อมูลก่อนยืนยัน

11. Bank Reconciliation และ Check Account

Bank Reconciliation

ไปที่ Bank Recon > New Reconciliation เลือกธนาคาร กรอกวันที่ จำนวนเงิน เลขเช็ค และหมายเหตุ ตรวจสอบใน Open Reconciliations หากบันทึกผิดให้ยกเลิกพร้อมเหตุผล

Check Account

เลือกปีและเดือนแล้วกดตรวจสอบ ระบบแสดงสถานะ Balanced/Out of Balance ยอด GL ยอด AP และส่วนต่าง หากไม่สมดุล ให้ตรวจ GL, AP, Payment และรอบบัญชี

12. รายงาน

รายงานหน้าที่
AP Agingวิเคราะห์เจ้าหนี้ค้างตามอายุหนี้
Vendor Cardรายการเคลื่อนไหวของผู้ขาย
Detail Ledgerรายการบัญชีแยกตามช่วงเวลาและ GL
Payment Registerรายการจ่ายเงิน
Invoice Registerรายการใบสำคัญ
Vendor Balanceสรุปยอดคงเหลือผู้ขาย
WHT Reportฐานภาษีและภาษีหัก ณ ที่จ่าย

กำหนดตัวกรองก่อนกดสร้างรายงาน และตรวจสอบช่วงวันที่ทุกครั้ง

13. การปิดงวด

Month-End

  1. ไปที่ Period > Month-End
  2. เลือกปีและเดือน
  3. ตรวจรายการค้าง ยอด Vendor และ Check Account
  4. ต้องเป็น Balanced ก่อนกดปิดงวด

Year-End

ไปที่ Period > Year-End ตรวจสถานะทุกเดือนและยอดรวม แล้วปิดปีเมื่อข้อมูลครบถ้วน

สำรองข้อมูลและให้ผู้มีอำนาจตรวจสอบก่อนปิดงวด

14. แก้ปัญหาเบื้องต้น

อาการแนวทางตรวจสอบ
ไม่เห็นเมนูตรวจ Role แล้วเข้าใช้งานใหม่
บันทึกไม่ได้ตรวจข้อมูลบังคับ รอบบัญชี และข้อความ validation
แก้เอกสารไม่ได้เอกสารอาจไม่ใช่ draft หรือรอบบัญชีปิดแล้ว
อนุมัติไม่ได้ตรวจ Role ผู้อนุมัติและสถานะเอกสาร
ยอดจ่ายเกินตรวจยอดคงค้างและยอดที่จับคู่แล้ว
Check Account ไม่สมดุลตรวจ GL, AP, Payment และรอบบัญชี
เลขที่ผิดให้ ADMIN ตรวจ Document Number และ Sequence

15. สำหรับผู้ดูแลระบบและ Developer

npm install
npm run dev
npm run lint
npm run type-check
npm run build
npm run db:push

ตัวแปรหลักใน .env.local: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY

ห้ามเปิดเผย SUPABASE_SERVICE_ROLE_KEY และห้ามใช้ข้อมูลจริงในบัญชีทดสอบ
